## AB-07.4 ProcessIdentity — the (pid, argv, starttime) tuple and its four verdicts
```mermaid
stateDiagram-v2
    [*] --> Launched
    Launched --> Captured: capture records pid, argv and starttime
    Captured --> Persisted: identity saved alongside the PID
    Persisted --> Verifying: caller is about to signal
    Verifying --> Match: same argv and same start time
    Verifying --> Mismatch: PID is live but is another process
    Verifying --> NoSuchProcess: PID is gone
    Verifying --> Inaccessible: proc could not be read at all
    Match --> Signalled: the ONLY verdict that permits a signal
    Mismatch --> Refused: refuse and report reuse
    NoSuchProcess --> TreatedStopped: refuse and treat as already stopped
    Inaccessible --> Refused: refuse and report, never assume a match
    Signalled --> [*]
    Refused --> [*]
    TreatedStopped --> [*]

    note right of Captured
        starttime is field 22 of /proc/pid/stat
        clock ticks since boot
        process_identity.rs:15-18
    end note
    note right of Match
        the kernel never reissues a pid plus starttime
        pair for a different process, so the pair is an
        identity not a guess - process_identity.rs:17-18
    end note
    note left of Verifying
        verify re-reads /proc IMMEDIATELY before the
        caller signals, never on an earlier verdict
        process_identity.rs:21-23
    end note
    note right of Inaccessible
        ProcError Inaccessible is never evidence about
        the target process, only about our own access
        process_identity.rs:47-49
    end note
    note left of Persisted
        /proc is reached through the ProcSource trait so
        tests inject a denied or absent procfs
        process_identity.rs:35-37 and :68-73
    end note
```
