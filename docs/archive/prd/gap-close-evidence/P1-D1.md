## What was built

`scripts/canary/d1-beam-check.sh` — the live-proof instrument for D1. D1's register mechanism
(a missing `connect()`, `resolveAgentPosition` hardcoded false) was **falsified**: the wire
exists in current code. Closure needs live proof that agent activity reaches the client data
path. This script supplies it, to be run against a running stack in the sprint-end live session.

- **Observes the exact client data path:** polls `GET /api/bots/agents` — the endpoint
  `AgentNodesLayer.tsx:444` polls. Parses the roster count from the `StandardResponse` envelope
  (`.data.count`, with `.data.agents[]` fallbacks; jq or python3).
- **Fires only on real live traffic:** on a genuinely non-empty roster it POSTs the observation
  to `POST /api/canary/observe/CANARY-VC-D1-BEAM` on the RES-a `LivenessHarness`. It is NOT a
  synthetic prober — no live agent, no fire (DDD invariant 5).
- **Honest timeout:** if no agent activity appears within `D1_MAX_ATTEMPTS × D1_INTERVAL_SECS`,
  it exits 2 WITHOUT firing — a correct non-closure, not a green stand-in.
- **Canary seeded:** `CANARY-VC-D1-BEAM` is registered in `P1_CANARIES` (`liveness_harness.rs`)
  so the observe POST lands on a declared wire (a fire on an unregistered canary is rejected 404).

### Exit codes

| code | meaning |
|---|---|
| 0 | non-empty roster observed and canary fired |
| 2 | timed out with no live agent data (canary correctly NOT fired) |
| 1 | hard error (stack unreachable, malformed response, observe rejected) |

## Falsification statement and how this survives it

> *WP-2 is falsified if `resolveAgentPosition` returns false at boot with live agent data
> present server-side, if `/api/bots/agents` returns empty while an agent is active, or if the
> D1 closure is declared without `CANARY-VC-D1-BEAM` having fired in a live session.*

- The script makes the closure conditional on `CANARY-VC-D1-BEAM` firing on observed live
  traffic; a closure asserted without a fire leaves the canary visibly `armed` in
  `GET /api/canary/status`.
- It fires on the exact `/api/bots/agents` roster the client consumes, so an empty roster while
  an agent is active would surface as a timeout (exit 2), not a false pass.

## Gap-close correction (2026-07-08, queen pass)

The P1 closure instrumented D1 (the `d1-beam-check` observation script and
`CANARY-VC-D1-BEAM`) but left the server-side poll trigger unwired:
`BotsClient::connect()` had zero call sites, so the 2-second agent-list poll
behind `/api/bots/agents` never started and the acceptance criterion "the poll
started at boot" was unmet in code. Corrected: `src/app_state.rs` now spawns a
fail-open boot task that calls `connect()` with backoff (5/15/60/300s) — an
unreachable MCP server logs and retries, never blocks boot. Receipt:
`cargo check -p visionclaw-server` clean at this commit. The canary remains the
proof that data flows; this correction closes the wire, not the claim.
