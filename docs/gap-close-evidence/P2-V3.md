## The proven gap (recon, carried forward)

PRD-023 WP-10 records V3 as literally-true "no conversational grounding":
`ConversationContext.pending_clarification` (`voice_commands.rs:88`) is *read* at
`voice_context_manager.rs:321` (`needs_follow_up`) but was **assigned nowhere** —
dead scaffolding. A low-confidence or under-specified spoken command was
dispatched straight to the selected agent with no repair opportunity.

## The fix

### 1. Pure gate + merge kernel — `src/services/voice_clarification.rs` (new)
- `ClarificationGate { threshold }` with `from_env()` reading
  `VISIONCLAW_VOICE_CONFIDENCE_THRESHOLD` (default **0.55**, clamped `[0,1]`,
  NaN → default) — the **configurable threshold**.
- Two gate triggers (WP-10 AC1): (a) STT confidence `< threshold`, (b) the
  **intent gate** — a spawn/stop command whose required slot (agent type / id)
  cannot be filled, mirroring `VoiceCommand`'s `extract_agent_type` /
  `extract_agent_id` error paths so gate and parser agree.
- `evaluate()` (first turn) → `GateOutcome::{Dispatch, Clarify}`. On `Clarify`
  the prompt **names what was heard** (quoted) **and the ambiguous slot**, and a
  `PendingClarification` is produced.
- `merge()` (repair turn): a low-confidence re-utterance **replaces** the
  mis-heard original; a missing slot is **filled** by appending the reply, then
  the merged transcript is re-gated — resolved → `Dispatch { merged }`,
  still-ambiguous → `Clarify` again.
- `PendingClarification::{to_token, from_token}` — compact `V3\u{1}slot\u{1}orig`
  encoding so the state fits the existing `Option<String>` field with no schema
  change; a foreign value decodes to `None` (no panic, treated as "no pending").

### 2. Cross-turn persistence — `src/services/voice_context_manager.rs`
- `set_pending_clarification(session, Some(token))` **assigns**
  `ConversationContext.pending_clarification` (creating the session if absent) —
  the WP-10 falsification trigger, now met. `take_pending_clarification` reads
  **and clears** it.

### 3. Wiring into the P1 governed path — `src/handlers/speech_socket_handler.rs`
- `VoiceCommandRequest` gains additive `confidence: Option<f32>`.
- New `SpeechSocket::process_governed_voice`: before dispatch, a repair turn
  merges the held clarification, else a fresh `evaluate`. On `Clarify` it holds
  the token, **speaks the clarification over Kokoro TTS**, emits a WS
  `voice_clarification` message, fires `CANARY-VC-V3-REPAIR`, and **does not
  dispatch**. On `Dispatch` it delegates to the existing `process_voice_intent`
  with the (possibly merged) transcript. The bound-DID branch now routes through
  this gate.
- `AppState` carries a shared `voice_context_manager` and the
  `clarification_gate` (built `from_env` at boot, threshold logged).
- `src/services/liveness_harness.rs`: `CANARY_V3_REPAIR` const + `P2_CANARIES` +
  `seed_p2_canaries()`, seeded at boot (`app_state.rs`).
