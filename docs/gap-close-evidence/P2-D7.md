## The fix

### Server — `src/agent_events/schema.rs`
- `AgentActionEnvelope` gains `intent: Option<String>`, additive and versioned
  exactly like the WP-7 CTC fields: `#[serde(default, alias = "declared_intent")]`
  so a producer that declares no intent still deserialises to `None`, both the
  register spelling `intent` and the fuller `declared_intent` parse, and the
  identity-blind binary `0x23` projection is unaffected (intent is legibility
  metadata, not a GPU field).
- Accessor `declared_intent(&self) -> Option<&str>`.
- The two `#[cfg(test)]` envelope literals (`agent_beam_actor.rs`,
  `provenance.rs`) carry the new `intent: None`.

### Client — `AgentDetailPanel` display
- `BotsAgent` gains `declaredIntent?: string`
  (`client/src/features/bots/types/BotsTypes.ts`).
- `BotsDataContext` maps it from node metadata
  (`declared_intent` / `intent`) — the join from the envelope field to the panel.
- `AgentDetailPanel.tsx` renders a distinct amber "Declared Intent — About to:
  <declared action>" block **above** the past-activity "Current Task", shown only
  when `declaredIntent` is present (never fabricated).
