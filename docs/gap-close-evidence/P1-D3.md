## What landed

- **Case queue against `GET /api/broker/inbox` (WS-12).**
  `client/src/features/control-center/governance/useBrokerCaseQueue.ts` fetches
  the inbox (the existing power-user-gated read surface), projects each case via
  the pure `toCaseView` (`brokerCaseQueue.ts`), and renders pending judgments in
  `AcspCaseQueue.tsx`.
- **Ambient ACSP indicator driven by the P0 `broker:*` WS events.** The hook
  subscribes to the multiplexed graph socket via `webSocketService.onMessage`,
  parses `broker:new_case` / `broker:case_decided` frames (pure `parseBrokerEvent`),
  and folds them into an open-case set (`applyBrokerEvent`, never mutating). The
  `AcspCaseQueue` pill shows the open-case count and reacts instantly to each
  event; the frames it consumes are exactly those `services/broker_events.rs`
  emits from the decide path.
- **Decide via the WS-9 enrichment decide route.** A new operator decide route
  `POST /api/broker/cases/{id}/decide`
  (`src/handlers/broker_inbox_handler.rs`, inside the `power_user()`-gated broker
  scope) funnels through the **same** decision core as the agentbox
  `X-Agent-Key` route: `enrichment_proposals_handler::decide` and the new
  `decide_as_operator` both call the extracted `apply_decision`, so there is one
  decision path (kernel + persistence + `broker:new_case`/`broker:case_decided` +
  `CANARY-VC-REC2-CASE`), not two. The operator's own pubkey attributes the
  decision (HITL provenance) when canonical; a malformed key downgrades to
  unattributed, never an error. The queue's Approve/Reject buttons POST this
  route.

## Falsification (PRD-023 WP-4, P1/UI half) → how it is met

*"…if the control centre shows no pending judgment while the forum holds an open
31402…"* — the control centre now fetches `/api/broker/inbox` and renders every
pending case, with the ambient indicator counting open cases and the `broker:*`
WS events keeping it live. *"…a case parks in `under_review` forever with no
decision path…"* — the operator route drives the kernel `DecisionOrchestrator`
and persists a terminal decision, emitting `broker:case_decided` and observing
`CANARY-VC-REC2-CASE` every call (the P0 core, now reachable from the UI). The
doc-honesty and `ElevationActor`-default clauses were met at P0 (`P0-REC-2.md`).
