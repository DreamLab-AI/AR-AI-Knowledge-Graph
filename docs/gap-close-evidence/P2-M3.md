## What landed

### 1. `proxemics.rs` — Hall's-zones arc solver (pure, deterministic)
- `solve(user_pos, user_forward, count, cfg) -> ProxemicsSolution { positions, radius_m, half_arc_rad }`.
- Defaults per the brief: **1.5–2.5 m social band**, **±60° forward arc**, `min_chord 0.6 m`, **never inside the 0.45 m intimate radius**. Agents at **equal angular spacing**; the **radius grows** within the band to keep the chord, and if the band is exhausted the **arc widens** (capped at ±85°) so agents never overlap as N grows.
- `should_resolve(...)` gates re-solving on a **membership change or a user pose/yaw delta threshold** (0.25 m / 0.15 rad) — keeps the solver off the per-frame path ("run only on membership/user-pose change").
- Property tests (`n = 1..=10`): `all_in_band_and_outside_intimate` (band respected, never inside intimate), `no_adjacent_overlap` (min chord held), `agents_stay_within_arc`, `deterministic`, `symmetric_about_forward_for_even_split`, `radius_grows_with_agent_count`, `placement_follows_user_facing`, plus the three `should_resolve` gates.

### 2. `avatar_state.rs` — activity machine + gaze-attention model
- **`ActivityMachine`**: `idle → working → awaiting_approval → speaking`, advanced by `AgentSignal` (task/approval/speech/idle) derived from agent-events / ACSP kinds. `speaking` is an **overlay** that restores the underlying activity on end (`speech_overlay_restores_prior_activity`, `…restores_awaiting_approval`, `stray_speech_end_is_noop`). Drives avatar colour/motion, not a skeleton (brief).
- **`GazeAttentionModel`** (time-driven): attention target per agent is `User | GraphNode(id) | None`. **Mutual gaze** engages only after the user dwells **>200 ms** on the agent (`mutual_gaze_requires_dwell_threshold`, `dwell_must_be_continuous`); it **holds** through a brief look-away (`mutual_gaze_holds_through_brief_lookaway`, 700 ms settle) and **releases** after the hold expires (`mutual_gaze_releases_after_hold_expires`) — the hysteresis that stops turret-snap. A **reaction latency** (150 ms) precedes re-aiming and a **bounded slew rate** (6 rad/s) makes the gaze **glide, not snap** (`gaze_slews_not_snaps`, `gaze_converges_to_target_over_time`). Task deixis drives gaze when there is no mutual gaze (`deixis_drives_attention_when_no_mutual_gaze`). Timing constants trace to Pejsa/Andrist/Gleicher/Mutlu per the brief.
- `AgentAvatar::presence()` produces the `AgentPresence { state, gaze_dir, attention }` snapshot for the wire.
- GDScript node `AgentAvatarNode` (apply_signal / tick_attention / getters + `activity_changed` signal), `cfg(not(test))` compile-verified.

### 3. Wire extension — `agent_presence.rs` (opcode 0x44, `visionclaw-xr-presence`)
- **Additive sibling of 0x43** (pose unchanged): per-agent `{state, gaze_dir (quantised), attention_target}` with a **per-agent field mask** that elides unchanged fields, mirroring the 0x43 `transform_mask` idiom.
- **Two channels, one codec**: `AgentPresenceDelta::channel()` routes discrete transitions (state / attention) to the **reliable** channel and gaze-only deltas to the **high-rate** (10–20 Hz) channel (`channel_routing_matches_field_semantics`).
- Gaze direction quantised to **16-bit-per-component** (`quantise_dir`/`dequantise_dir`), sub-milliradian error (`gaze_quantisation_preserves_direction`, cos θ > 0.9999). Delta compares gaze **at wire resolution** so sub-quantum jitter never hits the wire (`between_elides_subquantum_gaze_jitter`).
- Codec is **total** over arbitrary input (bounds-checked, no panics): round-trip tests (single keyframe, multi-agent mixed masks, empty batch, heartbeat), rejection tests (bad opcode / bad activity byte / bad attention tag / reserved mask bits / truncation), and property tests `agent_presence_round_trip`, `agent_presence_decode_is_total`, `agent_delta_apply_round_trip`.
- **Fuzz corpus entry**: new libFuzzer target `fuzz/fuzz_targets/agent_presence_decode.rs` (registered in `fuzz/Cargo.toml`) with a valid-keyframe seed at `fuzz/corpus/agent_presence_decode/keyframe_seed` (30 bytes). The in-process totality property `agent_presence_decode_is_total` runs under `cargo test` (cargo-fuzz nightly is the separate harness).
