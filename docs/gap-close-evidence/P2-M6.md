## Confirmation (ADR-130 Decision 1 says it does — cited)

`scripts/xr_boot.gd` `_ready()` sets `use_xr` **synchronously** after an explicit OpenXR `initialize()`:

```
xr_boot.gd:10   var xr_interface: XRInterface = XRServer.find_interface("OpenXR")
xr_boot.gd:11   if xr_interface == null: _show_error(...) ; return
xr_boot.gd:14   if not xr_interface.is_initialized():
xr_boot.gd:15       if not xr_interface.initialize(): _show_error(...) ; return
xr_boot.gd:18   get_viewport().use_xr = true          ← M6: set after a real init
xr_boot.gd:19   _probe_capabilities(xr_interface)
xr_boot.gd:22   _transition_to_graph_scene()
```

This is the Godot analogue of the WebXR `enterVR()`/`isXRMode` path; here the flag is set unconditionally once OpenXR reports initialised, so the session renders in XR, not as a desktop-as-VR view. `project.godot` `[xr] openxr/enabled=true`, `renderer/rendering_method="mobile"` (Forward Mobile, Quest 3) corroborate the XR session config.

## Eye-gaze hazard note (item 5, godot #113717)

`xr_boot._probe_capabilities` and `graph_scene._probe_eye_gaze` **only query** `is_eye_gaze_interaction_supported()` (behind a `has_method` guard), **after** OpenXR init, and never enable the `XR_EXT_eye_gaze_interaction` action-map binding. Quest 3 returns false, so the extension stays disabled and the action-map error (#113717) can never fire. The probed flag feeds the Rust gaze resolver, which keeps head-gaze primary.
