## The proven gap (adversarial re-verification)

A re-verifier traced the P1 interrupt fix to a dead end:

1. `src/utils/mcp_tcp_client.rs` has **no terminate/stop verb** — `McpTcpClient`
   exposes only `agent_list`, `swarm_status`, `server_info`, `initialize` and the
   generic `tools/call` wrapper. claude-flow-native agents cannot be stopped via
   MCP from this codebase, full stop.
2. `ManagementApiClient::TaskInfo.agent` only ever carries a **role label**
   ("coder"/"researcher"/…) — every `CreateTask` call site
   (`bots_handler.rs` hive-init/spawn-hybrid/settings/steer,
   `voice_interface_actor.rs`) passes a role. So the resolver's `t.agent == id`
   fallback could never match a claude-flow swarm `agent_id`.
3. The prior integration test only passed because its fake **fabricated** the join
   (put the swarm agent_id in the `agent` field).
4. agentbox `management-api/routes/tasks.js` destructured `agent` verbatim and
   never recorded a claude-flow id.

## The fix (three parts)

### 1. agentbox (own repo)
- `management-api/routes/tasks.js`: `POST /v1/tasks` accepts an OPTIONAL, additive
  `claude_flow_agent_id`; forwards it to `spawnTask`. `GET /v1/tasks` and task
  status echo `claudeFlowAgentId` (added to the fastify response schemas, else
  fastify strips it).
- `management-api/utils/process-manager.js`: `spawnTask(agent, task, provider,
  claudeFlowAgentId)` persists it on the task record; `getTaskStatus` /
  `getActiveTasks` echo it.

### 2. VisionClaw server
- `services/management_api_client.rs`: `create_task` / `create_task_with_context`
  carry `claude_flow_agent_id` (snake_case body key); `TaskInfo` + `TaskStatus`
  gain `claude_flow_agent_id: Option<String>` (camelCase, `#[serde(default)]`).
- `actors/task_orchestrator_actor.rs`: `CreateTask` gains
  `claude_flow_agent_id: Option<String>`; new typed `InterruptError`
  (`Unresolved` / `Transport` / `Stop`); the `InterruptAgentTask` resolver gains a
  **third branch `t.claude_flow_agent_id == id`, BEFORE any fallback**, and the
  `t.agent == id` fallback is **removed**.
- Call sites: all four in-repo `CreateTask` constructors pass `None` — none has a
  genuine claude-flow swarm agent_id at create time (do NOT fabricate; a task_id /
  role is not a claude-flow agent id). The join mechanism is integrated and proven;
  a claude-flow-native producer that knows the swarm agent_id at create time
  populates branch 3.
- `handlers/bots_handler.rs::interrupt_task`: matches `InterruptError::Unresolved`
  → **HTTP 422** with `resolution:"unresolved"`, `interruptible:false` (the client
  does not retry 4xx); other errors → 500.
- `tests/d2_interrupt_resolution.rs`: rewritten. The fake mirrors the REAL
  contract — it records the `claude_flow_agent_id` a `POST /v1/tasks` actually
  carried and echoes `claudeFlowAgentId` in `GET /v1/tasks` **only when the create
  carried it**. No fabricated joins.

### 3. Client honesty
- `client/src/features/bots/components/AgentDetailPanel.tsx`: on the distinct 422
  (or a 2xx `interruptible:false`), the interrupt control renders a disclosed,
  disabled explanatory state — "Externally spawned — not interruptible from here" —
  on the first failure, and is terminal (no retry). Reset when the selected agent
  changes.
- `client/src/features/bots/components/__tests__/AgentDetailPanel.notInterruptible.test.tsx`:
  unit-proves the state transition and that no second request fires.
